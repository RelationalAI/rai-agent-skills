# Evals — `rai-orm-from-workload`

Same conventions as [`rai-orm-from-schema/evals`](../../rai-orm-from-schema/evals/README.md): cases in `cases.json`, fixtures under `fixtures/<name>/`, reference outputs under `expected/`, results under `results/<YYYY-MM-DD>/` (not committed). Runs are manual and in-session, except where a case names a test file.

## What is tested

| Case | Question |
|---|---|
| W-E1 | Does the digest tool reproduce the expected digest for the SQL modality? |
| W-E2 | Does each modality (`sql`, `questions`, `pairs`) yield the evidence it can, and only that? |
| W-E3 | Does any SQL literal or question text leak into the digest or the model? |
| W-E4 | With the digest, does the SRP propose what the evidence supports and nothing else? |

The verification loop is tested in [`rai-orm-verify/evals`](../../rai-orm-verify/evals/cases.json) on the same fixture.

## Quick start

```
cd skills/rai-orm-from-workload
python -m pytest -q tools                       # W-E1 and the literal check of W-E3
sqlite3 /tmp/campus.db ".read evals/fixtures/campus/schema.sql" ".read evals/fixtures/campus/data.sql"
```

Then, in a session with the ORM skills loaded, once per modality:

> Use rai-orm on the database /tmp/campus.db with the workload `evals/fixtures/campus/workload.pairs.json`. One-shot.

Compare the outputs with the targets in `cases.json` and the table in [`fixtures/campus/README.md`](fixtures/campus/README.md).

## Status of the expected files

`expected/campus.sql.digest.yaml` is generated by the tool and has not yet been reviewed line by line. The `terms` and alignments of the `questions` and `pairs` modalities have no expected file: W-E2 checks them by targets, because term lists legitimately vary in wording.
